# FinSight

Учебный проект анализа документов. На текущем этапе реализованы классификация
и хранение документов, извлечение сущностей и финансовая тональность;
резюме, RAG и интерфейс ещё предстоит добавить.

## Что работает

- Классификация английского текста: Financial, General, Legal, News, Scientific, Technical.
- Загрузка TXT в UTF-8, PDF с текстовым слоем и DOCX с абзацами и обычными таблицами.
- Разбиение документа на блоки до 120 слов и дополнительное разделение блоков,
  превышающих 512 токенов. Все полученные части участвуют в классификации без обрезки.
- Сохранение оригинального файла, извлечённого текста и результата в PostgreSQL.
- Список, карточка и удаление документа по UUID.
- Извлечение организаций (`ORG`), денежных сумм (`MONEY`), дат (`DATE`) и процентов
  (`PERCENT`) готовой английской моделью spaCy `en_core_web_sm`.
- Финансовая тональность английского текста готовой моделью
  [ProsusAI/finbert](https://huggingface.co/ProsusAI/finbert): positive, negative, neutral.
  Анализ доступен при загрузке документа и отдельно через `POST /sentiment`.

Формат `.doc`, OCR сканов и гарантированная классификация русского текста пока не поддерживаются.
Каждая загрузка создаёт отдельный документ, даже если исходное имя совпадает.

## Локальный запуск

Нужны Python 3.13+, uv и запущенный PostgreSQL. Docker для текущего запуска не требуется.
В проекте настроен источник PyTorch с CUDA 12.8; установка зависимостей включает соответствующую сборку.

1. Клонируйте репозиторий и установите зависимости:

   ```powershell
   git clone https://github.com/bachaa7/FinSight.git
   cd FinSight
   uv sync --locked
   ```

   Пакет английской модели spaCy закреплён прямой ссылкой в зависимостях и
   устанавливается вместе с ними. После установки NER работает локально.

2. Создайте пустую БД через pgAdmin / SQL-клиент, подключённый к существующей базе,
   например `postgres`:

   ```sql
   CREATE DATABASE finsight;
   ```

3. Создайте `.env` из `.env.example`, затем укажите собственные параметры PostgreSQL:
   `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.

   ```powershell
   if (-not (Test-Path .env)) { Copy-Item .env.example .env }
   ```

   Сам `.env` исключён из Git. В `.env.example` хранятся только примерные настройки.
   `SecretStr` скрывает пароль при обычном выводе объекта, но не шифрует файл.

4. Примените миграции к созданной базе:

   ```powershell
   uv run alembic upgrade head
   uv run alembic current
   ```

   Миграции создают таблицы `documents` и `alembic_version`, но не саму базу PostgreSQL.
   Код миграций входит в Git; пользовательские записи и файлы — нет.

5. Разместите сохранённую модель из ноутбука `ml/notebooks/03_distilbert.ipynb`
   в `models/distilbert_doc_classifier/`: веса, конфигурацию и файлы токенизатора,
   полученные через `save_pretrained`. Каталог моделей исключён из Git.
   Приложение загружает эту локальную модель при старте; автоматического обучения
   или скачивания готового артефакта сейчас нет.

   Для тональности при первом запуске Transformers скачивает FinBERT в кэш
   Hugging Face (`HF_HOME`, если переменная задана). Сама модель DistilBERT остаётся
   локальным артефактом обучения, а spaCy устанавливается как пакет — это три разных
   способа подключения моделей. После скачивания анализ выполняется локально.

6. Запустите API из корня репозитория:

   ```powershell
   uv run fastapi dev src/finsight/api/main.py
   ```

   Swagger: <http://127.0.0.1:8000/docs>. Режим `dev` автоматически перезапускается
   после изменения кода. Миграции повторно применяются отдельной командой.

## API

| Метод и путь | Назначение | Успех |
|---|---|---|
| `GET /health` | Статус приложения и классы модели | 200 |
| `POST /classify` | Классификация JSON-поля `text` | 200 |
| `POST /sentiment` | Финансовая тональность JSON-поля `text` | 200 |
| `POST /documents` | Загрузка файла через multipart-поле `file` | 200 |
| `GET /documents` | Сохранённые документы, новые первыми | 200 |
| `GET /documents/{document_id}` | Карточка с извлечённым текстом | 200 |
| `DELETE /documents/{document_id}` | Удаление записи и оригинального файла | 204 без тела |

Загрузка ограничена 20 × 1024 × 1024 байт (20 МиБ). Для JSON-запроса `/classify`
и `/sentiment` действует отдельное ограничение: от 1 до 20 000 символов;
текст из одних пробелов отклоняется.
Неподдерживаемый формат даёт 415, превышение размера — 413, некорректный ввод — 422,
отсутствующий документ — 404. UUID и дата сериализуются в JSON-строки.

В ответах загрузки и списка нет полного текста и внутреннего пути хранения.
Поле `text` возвращается только в карточке. Список пока выдаётся целиком, без пагинации.

Ответы загрузки, списка и карточки содержат `entities`: список объектов
`{text, label, start, end}`. `start` — начальный индекс символа, `end` — правая
невключительная граница в сохранённом извлечённом тексте, не в байтах файла:
`document_text[start:end] == entity_text`. Начальные пробелы и переносы учитываются.
Повторные упоминания сохраняются отдельно, чтобы не терять позиции.

`entities: null` означает, что NER ещё не выполнялся (например, для старых загрузок).
`entities: []` означает обработанный текст без подходящих сущностей. Старые документы
автоматически не пересчитываются; можно загрузить файл заново. При чтении карточки
используется сохранённый результат, а NER повторно не вызывается.

Модель NER используется без дообучения. Её английские предсказания могут ошибаться;
`ORG` включает не только компании, но и другие организации. Биржевые тикеры отдельно
не извлекаются. NER получает полный исходный текст независимо от блоков классификатора.
У spaCy есть собственный лимит длины текста (`nlp.max_length`); превышение сейчас
возвращает 422. Дополнительное разбиение очень длинных текстов для NER не реализовано.

Поле `sentiment` содержит `label`, `confidence`, `score` и `probabilities`.
Для длинного текста вероятности трёх классов усредняются по всем обработанным блокам.
Метка выбирается по максимальной средней вероятности; `confidence` — её значение;
`score = probabilities["positive"] - probabilities["negative"]` находится в [-1, 1].
У нейтральной метки score может немного отличаться от нуля. Confidence не является
измеренной точностью модели, а score не предсказывает изменение цены актива.

В `chunking.py` находится общее разбиение с явным параметром `tokenizer`:
DistilBERT передаёт собственный токенизатор, FinBERT — собственный. Текст не обрезается.
Текущее усреднение даёт каждому блоку одинаковый вес; это простой базовый подход,
который не учитывает различия в длине блоков и противоречия отдельных фрагментов.
Для старых документов `sentiment: null` означает отсутствие анализа;
это не нейтральная оценка. Пересчёт старых документов автоматически не запускается.

## Как устроено хранение

- `src/finsight/config.py` — чтение и проверка настроек из `.env`.
- `src/finsight/database.py` — Engine и отдельная Session на запрос.
- `src/finsight/models.py` — таблица документов, JSONB с результатом классификации.
- `src/finsight/ml/entities.py` — NER и фильтрация нужных типов сущностей.
- `src/finsight/ml/sentiment.py` — FinBERT, усреднение и итог тональности.
- `alembic/` — история изменений структуры БД.
- `src/finsight/documents/storage.py` — запись и удаление оригиналов.
- `data/uploads/` — локальные файлы с именем `<UUID>.<расширение>`.

В БД сохраняется имя файла относительно папки загрузок. В исходный документ
при классификации изменения не вносятся. Для переноса документов нужны и данные
PostgreSQL, и папка загрузок; копирование одного репозитория их не переносит.

Файловая система и PostgreSQL не образуют общую транзакцию. При ошибке сохранения
записи приложение откатывает транзакцию и пытается удалить уже записанный файл.
При удалении сначала фиксируется удаление записи, затем удаляется файл. Если второе
действие не удалось, API сообщает о частичном результате: запись удалена, файл остался.
Автоматическая повторная очистка оставшихся файлов пока не реализована.

## Тесты и оформление

```powershell
uv run pytest
uv run ruff check src tests alembic
uv run ruff format --check src tests alembic
```

Обычные тесты не требуют модели, `.env` и запущенного PostgreSQL: нейросеть и Session
подменяются, файлы создаются только во временных папках. Они проверяют поведение кода
и HTTP-контракт, но не качество обученной модели.

Дополнительно можно проверить цепочку миграций и операции API на настоящем
PostgreSQL, используя настройки `.env`:

```powershell
$env:FINSIGHT_TEST_POSTGRES = "1"
uv run pytest tests/test_postgres_documents.py -v
Remove-Item Env:\FINSIGHT_TEST_POSTGRES
```

Эти тесты требуют права создавать схемы. Для каждого теста создаётся отдельная схема
с уникальным именем. Работа идёт во внешней транзакции с SAVEPOINT; в конце она
откатывается вместе с тестовыми таблицами и записями. Пользовательская таблица
`public.documents` в этих тестах не используется.

Для будущих изменений моделей:

```powershell
uv run alembic revision --autogenerate -m "describe schema change"
# Просмотрите сгенерированный файл перед применением.
uv run alembic upgrade head
```

HTML-конспект `docs/classifier-guide.html` — локальный учебный материал,
по договорённости он исключён из Git.

## Если сеть мешает запуску

Обычный `uv run` перед запуском проверяет и при необходимости синхронизирует
окружение проекта. Если GitHub недоступен, эта стадия может завершиться таймаутом
на пакете `en-core-web-sm`, даже когда пакет уже установлен. Миграция или сервер
в этом случае ещё не начали выполняться.

Для уже установленного окружения можно пропустить синхронизацию:

```powershell
uv run --no-sync alembic upgrade head
uv run --no-sync alembic current
uv run --no-sync fastapi dev src/finsight/api/main.py
```

Если все файлы FinBERT уже скачаны, можно дополнительно отключить обращения
Hugging Face к Hub для текущего терминала:

```powershell
$env:HF_HUB_OFFLINE = "1"
uv run --no-sync fastapi dev src/finsight/api/main.py
# Вернуть обычный режим Hugging Face:
Remove-Item Env:\HF_HUB_OFFLINE
```

`--no-sync` управляет окружением uv, а `HF_HUB_OFFLINE` — загрузкой файлов моделей;
одно не заменяет другое. Они не устанавливают отсутствующие зависимости и модели.
После изменения зависимостей нужна успешная синхронизация (`uv sync`) при доступной сети.
Локальное соединение с PostgreSQL от `HF_HUB_OFFLINE` не отключается.

Готовность сервера подтверждает `Application startup complete`. Сообщение
`Using cached commit hash` означает использование кэша после неудачной проверки Hub.
`Shutting down` с корректным завершением показывает остановку сервера, но само
по себе не объясняет, кто её инициировал. Dev-режим может повторно загружать модели
при старте и перезапуске; это не повторное обучение.
